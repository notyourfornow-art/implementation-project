# План возврата (Rollback) v1.2.0

## Триггеры
- Сервис недоступен более 5 минут после deployment
- Рост ошибок backend > 50 за 10 минут
- Невозможность создать заявку (критический сценарий)
- Риск повреждения данных

## Процедура (целевое время ≤ 15 минут)
1. Остановить backend и notifications
2. Восстановить предыдущую версию: `bash scripts/rollback/rollback.sh v1.1.0`
3. Откатить миграцию: `bash scripts/rollback/rollback-migration.sh`
4. Восстановить БД из backup (если миграция необратима): `bash scripts/rollback/restore-db.sh`
5. Запустить сервисы, выполнить smoke-тест
6. Уведомить участников и пользователей о возврате

## Особые риски
- Миграция `002_add_notifications` добавляет колонку `priority` — обратима
- Таблица `notifications` создаётся без данных — обратима
- **Необратимых изменений нет** — откат без потери данных возможен

## Контакты для эскалации
- DBA: Сидорова (restore БД)
- Разработчик: Петров (причина сбоя)
